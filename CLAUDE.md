# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`volto-dropdownmenu` is a generic Volto add-on (plain JS/JSX, not TypeScript) providing a configurable mega/dropdown main navigation. It is the frontend counterpart of the Plone backend add-on [`collective.volto.dropdownmenu`](https://github.com/collective/collective.volto.dropdownmenu), which provides the `@dropdown-menu` REST endpoint and the `dropdown-menu-settings` control panel.

It is published to npm and can also be checked out into a Volto project with `mrs-developer` (see README). The code requires **Volto ≥ 19** (see `peerDependencies`); projects on Volto < 19 use v4.1.6.

## Commands

The package has no standalone build or test setup — it is compiled and run by a host Volto project that lists it in its add-ons.

```sh
pnpm prettier         # check formatting of src/**/*.{js,jsx}
pnpm prettier:fix     # fix formatting
pnpm i18n             # extract messages into locales/ (uses @plone/scripts `i18n --addon`)
pnpm dry-release      # release-it dry run (tags v${version}, auto-changelog, npm publish)
```

Linting uses the host project's ESLint config, e.g. from the host frontend root: `pnpm exec eslint <path-to>/volto-dropdownmenu/src`.

## Architecture

- **`src/index.js`** – `applyConfig`:
  - registers the `menu_configuration` widget (by field id) used by the backend control panel,
  - registers `MenuConfigurationForm` in the component registry (projects can override it via `config.registerComponent`),
  - adds the `dropdownMenuNavItems` addon reducer,
  - adds an `asyncPropsExtenders` entry on `/` so menu data is fetched during SSR,
  - sets `config.settings['volto-dropdownmenu'].options.clickableNavigationRoots` (default `false`; when `true` the editor form shows a per-item checkbox).
- **Data flow**: `actions/getDropdownMenuNavitems` → GET `/@dropdown-menu` → `reducers` stores `state.dropdownMenuNavItems.result`. The result is a list of `{ rootPath, items: [...] }`; `utils.getItemsByPath(items, pathname)` picks the config with the longest matching `rootPath`, falling back to `/`. See `menuConfigurationExample.json` for the data shape (items have `mode` `simpleLink`|`dropdown`, `linkUrl`, `navigationRoot`, `showMoreLink`, and Volto `blocks`/`blocks_layout`).
- **`src/widget/`** – editor UI, all lazy-loaded via `@loadable/component` into the `volto-dropdownmenu-manage` chunk. `MenuConfigurationWidget` edits the JSON (root paths → menu items); `MenuConfigurationForm` edits a single item, including an embedded visual Volto `Form` for blocks (note its custom Enter-key handling so Enter only works inside `.menu-blocks-container`).
- **`src/components/DropdownMenu.jsx`** – renders an open dropdown panel (navigation roots, blocks rendered via `config.blocks.blocksConfig`, footer link).
- **`src/customizations/components/theme/Navigation/Navigation.jsx`** – replacement for Volto's `Navigation`, only active if the host project adds `.../volto-dropdownmenu/src/customizations` to `customizationPaths`. Projects may instead write their own `Navigation` customization importing `volto-dropdownmenu/components/DropdownMenu`, `/actions`, `/utils`, `/hooks/useOutsideClick` — treat those module paths as public API and keep them stable.

## Volto 19 notes

- Import from full Volto module paths (e.g. `@plone/volto/helpers/Url/Url`, `@plone/volto/helpers/Blocks/Blocks`) rather than barrel files like `@plone/volto/helpers`, following Volto core's own convention. Imports starting with `~` are no longer supported.
- `config.settings.isMultilingual` is gone; read `state.site.data.features.multilingual` instead.
- Outside-click handling uses the local `src/hooks/useOutsideClick.js` instead of the unmaintained `react-outside-click-handler` dependency.
- Keep the `__SERVER__ &&` guard in the `asyncPropsExtenders` promise (same pattern as Volto core's `getSiteAsyncPropExtender`): asyncConnect also runs on every client-side navigation, and `Navigation` already fetches the menu on the client. Non-promise results are fine, asyncConnect checks `isPromise()`.

## Conventions

- All UI strings go through `react-intl` `defineMessages`. New message ids use the `dropdownmenu-…` prefix (a few older ones such as `Close menu` reuse Volto's ids). Run `pnpm i18n` after adding messages (locales: de, en, es, eu, fr, it, ja, nl, pt, pt_BR, ro).
- Changelog (`CHANGELOG.md`) is generated by `auto-changelog` during `release-it`; don't edit it by hand.
